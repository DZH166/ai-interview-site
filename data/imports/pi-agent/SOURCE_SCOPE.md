## 编写与核验方法

执行机制、上下文与会话、业务生产工程分别精读相关官方源码、文档、类型及测试，并记录在 `evidence-runtime.md`、`evidence-context.md`、`evidence-production.md`。已有 DG 教程和视频笔记用于选择学习难点，不作为 Pi 当前行为的最终证据。

主要机制包括：

- Agent Loop 与 Agent 状态封装、流式消息、工具参数准备/校验/执行/结算、并行顺序、两条消息队列。
- AgentSession 的任务收尾、重试、同一次运行中的压缩、资源装配、消息转换和默认 JSONL 会话树。
- Skills、Extensions、SDK、stdio RPC 与实验性远程代码的发布边界。
- 模型 Provider 差异、用量统计、假模型测试、工具权限与进程隔离。
- 新 AgentHarness 的持久操作状态、重放政策与外部副作用边界。

题目中的 `fact_scope` 区分源码事实与工程设计方案。多用户鉴权、业务数据授权、限额、评测任务、补偿操作等是方案建议，除非引用明确证明，否则不称为 Pi 开箱即用能力。

## 与旧资料的关键差异

1. v0.85.1 Agent 构造接口要求显式 `streamFn`；已编译老调用的兼容兜底不代表新 TypeScript 接口允许省略它。
2. `prepareNextTurn` 在将开始下一轮时工作；新 AgentSession 可在工具结果返回后、下次模型调用前进行压缩，不能沿用“只能等整个 run 结束”的旧说法。
3. `Agent.subscribe` 的异步监听器会被等待；`AgentSession.subscribe` 的通知语义不同，不能混为事务持久化屏障。
4. 经典 Coding Agent 的 `SessionManager` 与新 Harness 的 Session/存储接口是不同路径；不能按同名字段直接互换。
5. v0.85.1 发行说明明确：实验 `client`、`experimental/plugin` 子路径及 server/client 命令为 source-only，经 `pi-test.sh` 使用；受支持本地 SDK 和 stdio RPC 不因此变为不可用。
6. 内置工具不只默认的四个；新版本还含可选 `powershell`。默认工具与可选工具、工具白名单与 OS 沙箱分别是不同概念。
7. `AgentSession.prompt()` 只有实际启动运行的分支才等待运行收尾；排队、扩展命令和 input 已处理分支可以提前返回。文档的笼统表述需要用源码分支限定。
8. 新 Harness 的模型恢复先将已提交片段结算为中断结果，但后续仍可能按持久重试政策发起新尝试；合成记录中的零用量不表示供应商实际没有计费。

## 这次实际验证了什么

题库内容采用静态源码与测试规格审阅，没有运行完整 Pi 测试套件，没有调用真实模型，也没有为 30 个练习编写或运行实现。

本包 `scripts/build.mjs` 可离线校验：JSON 字段、30 个连续唯一主 ID、3 类各 10 题、90 个嵌套追问、每题 10 分规则、前置关系、固定来源路径、导入哈希及 Markdown 与 JSON 同步。`--self-test` 使用故意损坏的数据检查校验器会拒绝缺题、重复 ID、缺答案、非法评分和版本漂移等情况。

这些检查不等同于目标工作台的实际导入测试、在线模型评测或学习者掌握程度。接入 Agent 仍需在目标工作台执行首次导入、重导、读回和保留用户作答等验收。
