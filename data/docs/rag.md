RAG 是实习应用岗面试的绝对重心,因为它是当前企业落地最多的模式。这一章按"是什么 → 怎么建 → 怎么查 → 答错了怎么办"组织。

## RAG 是什么:开卷考试

模型参数里的知识固定且过时;RAG 让模型答题前先查资料——问题向量化 → 检索 top-k → 拼进提示词 → 基于资料生成并引用。解决三件事:知识新鲜、私有知识、可追溯。它和微调的分工:RAG 管"知识",微调管"行为"。

→ 对应练习:[RG-001](#/study/RG-001)

## 建库管线:切分是性价比最高的杠杆

离线管线:加载 → 解析 → 清洗 → **切分** → Embedding → 入库。切分为什么必须:Embedding 有输入上限;整篇一个向量会稀释主题。策略上推荐结构感知切分(按标题层级、保表格完整、块内补标题路径),配合父子块(检索用小块、生成用父块)。参数(size/overlap)不要拍脑袋,用小标注评测集跑召回率来定。

元数据(来源、标题路径、版本、日期)是新手最容易忽略的部分——引用展示、版本过滤、权限隔离全靠它。

→ 对应练习:[RG-002](#/study/RG-002)

## 检索:语义与关键词的互补

Embedding 把文本映射成"意思坐标",语义相近则向量相近,检索用余弦/内积找最近邻,生产用 HNSW 等 ANN 索引换速度。但向量检索对精确符号(错误码、型号)弱、对"相似不相关"内容会误伤——所以生产标配 **BM25 关键词 + 向量**双路召回,RRF 融合,再用交叉编码器 rerank 精选 3~5 块。

→ 对应练习:[RG-003](#/study/RG-003)

## 答错了:四段故障分类法

这是区分"调过 RAG"和"只会改提示词"的分水岭题。任何"答错"都拆成四类,排查从"检索回来的原文里有没有正确答案"这一刀切开:

1. **语料没有答案** → 补数据、准入清单、空检索拒答;
2. **检索没找对** → query 改写、混合检索、rerank、父子块;
3. **上下文组织不当** → 控制块数、高分前置、来源版本标注、冲突提示;
4. **生成不遵循证据** → 硬约束提示、句级引用、忠实度自动校验、低温。

配套体系:trace 日志(没有日志一切白搭)+ 分层指标(检索 recall@k / 生成忠实度)+ 回归评测集(修复必须跑分)。

→ 对应练习:[RG-004](#/study/RG-004)、[EN-002](#/study/EN-002)

## 学习建议

按 RG-001 → RG-002 → RG-003 → RG-004 的顺序学,前三题是"正向链路",第四题是"反向排查"。面试时能主动画出两条管线图 + 故障四分类,基本就超过多数候选人了。
