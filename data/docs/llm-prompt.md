调用大模型看起来就是发一个 HTTP 请求,但面试官想知道的是:**当请求量、失败、成本、格式要求一起砸过来时,你的系统还能不能稳定产出**。这一章把这四件事串起来。

## 采样参数:控制"怎么选词",不是"聪明程度"

模型每一步输出一个概率分布,temperature 调分布的尖锐程度,top_p 动态截断候选。记住边界:**它们改变表达,不改变知识**——低温不能减少事实性幻觉,高温也不代表更有创造力。按任务选值:抽取/代码 0~0.3,常规问答 0.3~0.7,创意适度调高。

→ 对应练习:[LP-001](#/study/LP-001)

## 上下文窗口:一次请求的预算表

三个必背事实:①窗口 = system + 历史 + 检索内容 + 本轮输入 + 输出预留,输入输出**共享**;②模型**无状态**,多轮记忆是应用层每次重传 messages 实现的;③历史管理 = 截断旧轮 / 摘要压缩 / 外部记忆检索,三招按开销递增。

与它常一起被问的是"上下文窗口和参数量的区别":窗口是运行时额度,参数量是训练固化的权重——一个是桌面能摊开的资料页数,一个是脑子本身。

工程技巧:稳定内容(system 提示、知识库背景)放提示最前面,让平台的前缀缓存命中,省钱又提速。

→ 对应练习:[LP-002](#/study/LP-002)

## 结构化输出:三档可靠性与服务端闭环

按可靠度递增:提示词约束 < JSON mode < 结构化输出(strict,按 JSON Schema 约束解码)。官方文档明确说结构化输出"仍可能有内容错误",所以**服务端必须**有 Pydantic 校验 + 带错误回喂的重试 + 最终降级。这个闭环结构是本题的得分核心:schema 保证"形",业务校验保证"义"。

→ 对应练习:[LP-003](#/study/LP-003)

## 错误处理:先分类,再动作

429 → 退避重试(指数 + 抖动,遵守 Retry-After);超时/5xx → 少量重试 + 必设超时;4xx → 程序错误,告警而不是重试。系统层面:全局并发控制把 429 压在源头,熔断防雪崩,降级链(主模型→备用模型→缓存→兜底话术)保可用。重试要有上限,有副作用的调用要幂等。

→ 对应练习:[LP-004](#/study/LP-004)、[EN-001](#/study/EN-001)

## 一条面试主线

把四节串成一句话:**"我做 LLM 调用层时,按任务设定采样参数,把上下文当预算管理,结构化输出一律配服务端校验闭环,错误按可重试性分类处理"**——这句主线能自然引出每一节的深入追问。
