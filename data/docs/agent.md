## 概念框架:Agent vs 工作流

分界线一句话:**谁决定流程**。工作流 = 开发者预定义代码路径编排 LLM(链式/路由/并行/编排者-执行者/评估-优化五种模式);Agent = LLM 动态主导流程与工具使用,本质是"在一个循环里基于环境反馈使用工具的 LLM"。Anthropic 的建议是从最简单方案开始——很多场景单次调用+检索就够,Agent 用延迟和成本换灵活性,且错误会复合。

→ 对应练习:[AG-001](#/study/AG-001)

## 工具调用:模型只"点名",从不执行

五步循环:定义(名称+描述+JSON Schema)→ 模型返回调用意图 → **你的代码**校验并执行 → 结果回传 → 模型继续,直到不再调用工具。所有外部访问都经你的代码,这是安全边界;参数错误回传给模型让它自愈,这是可靠性来源;工具定义占 token,大系统要做工具发现——这正是 MCP 的用武之地。

→ 对应练习:[AG-002](#/study/AG-002)

## 可靠性:失败恢复与人工介入

四层机制,目标是"失败可控、可恢复、可归因":

1. **预算**:最大步数 / token / 费用,到线即停并如实汇报;
2. **错误分层**:参数错回传自愈 / 瞬时故障代码退避 / 系统性失败终止转人工;
3. **检查点 + 幂等**:状态机落库可恢复,幂等键防重复扣款;
4. **审批闸门**:不可逆高影响动作(付款/删除/对外发送)必须人工确认。

→ 对应练习:[AG-003](#/study/AG-003)

## MCP:工具生态的 USB-C

MCP 是连接 AI 应用与外部系统的开放标准,把 M×N 集成问题变成 M+N。服务器暴露工具/资源/提示三类原语,底层 JSON-RPC。定位要准确:MCP 是连接与发现层,模型侧机制仍是 function calling;安全(最小权限、提示注入防护)不会因标准化自动解决。

→ 对应练习:[AG-004](#/study/AG-004)

## 状态管理与记忆(预备知识)

面试常追问 Agent 的"记忆":短期记忆=上下文窗口里的对话与中间结果(见 [LP-002](#/study/LP-002));长期记忆=外部存储(向量库/数据库)按需检索。任务状态(检查点)与对话记忆是两回事,别混着答。多智能体协作属进阶内容,实习岗了解概念即可,见进阶专题说明。
