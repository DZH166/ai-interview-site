应用开发岗的原理题有明确的"够用深度":面试官想确认你理解黑盒里发生了什么,而不是让你推导反向传播。这一章给出这个深度。

## Token:模型世界的"字"

模型不认识"字",只认识 token(词元):文本先被切分成 token 再进入模型,计费、窗口、速度全部按 token 算。中文一个字通常是 1~2 个 token(依分词器而定),所以中文对话比英文"更贵"。理解 token 就能理解:为什么 max_tokens 是输出预留、为什么上下文窗口按 token 而不是按条数计。

## 向量:语义的坐标

Embedding 把文本映射成高维向量,训练目标是"意思近的文本坐标近"(对比学习)。检索=找坐标最近的 K 段([RG-003](#/study/RG-003))。要记住边界:坐标近是"模型学出的意思近",不保证相关,对精确符号弱——这是混合检索存在的理由。

## 注意力与 Transformer:每个词都在"开会"

每个 token 生成 Query/Key/Value 三种向量,用 Q 对所有 K 打分,softmax 成权重后加权求和 V——每个位置一步聚合全句信息;多头让不同子空间学不同关系;位置编码补上顺序信息。Transformer 由此可全并行训练,这是大模型时代的架构起点。

工程含义(应用岗重点):推理是自回归的逐 token 过程,KV Cache 是加速关键;长上下文的成本来自注意力的 O(n²) 与 KV Cache 显存。

→ 对应练习:[FD-001](#/study/FD-001)

## 幻觉:训练目标决定的"天性"

模型优化"下一个词的概率",事实性只是间接相关——流畅的编造与正确的陈述在训练信号里可能同样高分。叠加知识截止、数据错误、被逼"必须回答"的提示压力。工程对策:事实类问题走工具与 RAG、句级引用+忠实度校验、明确的拒答通道。目标不是"消除",而是"降低概率 + 快速发现 + 限制危害"。

→ 对应练习:[FD-002](#/study/FD-002)

## 训练与推理、窗口与参数(高频对比题)

- 训练 vs 推理:训练更新参数、可并行;推理参数冻结、自回归逐 token;
- 上下文窗口 vs 参数量:一个是单次请求能读入的额度(运行时),一个是固化权重规模(能力上限)。

这类"对比题"在面试里出现率极高,建议成对记忆。
