======AG-002 工具调用(function calling)的完整流程是什么?模型真的在『执行』工具吗?
  plain(81): 模型像填写一张操作申请单，真正执行的是宿主程序。申请单填对了不等于有权限，程序返回了也不等于业务目标已达到。这个分工比“模型会调用函数”更能说明错误和责任在哪里。
  answer(119): 工具调用的基本链路是：提供能力描述与参数schema，模型提出调用，宿主校验并执行，结果回传，再由模型或程序决定后续。模型没有因为输出函数名就执行代码。格式有效、获得授权、操作成功和结果正确是不同关卡；多次调用与并行调度由具体运行时管理。
  pitfalls: ["把tool call当执行结果。", "用schema通过代替权限和业务检查。"]
======AG-004 MCP(Model Context Protocol)是什么?它解决什么问题?和 function calling 什么关系?
  plain(67): 可以把协议看成约定好的接口，把模型工具调用看成申请单格式。宿主负责把申请单交给接口，也可以由普通程序发请求；二者不是缺一不可的依赖链。
  pitfalls: ["FC→MCP→Skill是不可跳过的强制依赖链。", "把连通、兼容、授权和安全当成同一件事。"]
======AD-004 LoRA 的秩(r)和目标模块怎么选?秩越大效果越好吗?
  plain(93): 把低秩更新想成用少数方向调整一个大矩阵。方向多了可表达的变化更多，但未必更符合真实任务；调整哪些层也不能机械等同“QKVO只学表达、FFN只存知识”。这只是直觉，不是模型功能的精确分区。
  answer(111): LoRA的r决定低秩更新的容量上界，不是越大越好，也没有统一适合所有任务的秩区间。目标投影层、训练数据和优化配置共同影响表现。应在固定验证集与资源预算下比较多个候选，同时检查通用能力回归；训练损失更低不能单独证明选择更好。
  deep tail(194): …标层是实验变量
可以从实现支持的注意力投影或更多线性层做候选。记录所选层、r、缩放、数据和验证结果，不宣称唯一正确配置。
  pitfalls: ["把经验超参区间说成定理。", "把适配器参数占比当成总训练显存占比。"]
======AD-005 QLoRA节省哪些显存，哪些效果与硬件结论必须验证？
  plain(79): 基座像压缩存放的设备，工作时仍要展开参与计算，训练的主要是旁路适配器。省了存储不等于省掉所有中间过程；低精度也可能改变结果。这个类比不提供具体速度和精度承诺。
  pitfalls: ["把理想权重字节数当作训练总显存。", "把论文单48GB实验泛化成任意双24GB配置保证。"]
======AD-008 GRPO 是什么?它和 PPO/DPO 在概念上怎么区分?
  plain(72): 可以把一组候选答案放在同一道题下比较相对表现，而不是另训一个价值预测器。但如果评分本身有偏差，组内比较同样会被误导；算法不替你定义什么是好答案。
  deep tail(176): …## 资源与验收
固定采样量、长度、模型角色和优化配置再测资源；监控奖励投机与业务质量，不把奖励上涨直接当真实能力增长。
  pitfalls: ["把GRPO与RLVR画成相同概念。", "用少一个模型角色推导固定显存比例。"]
======AD-011 PagedAttention 和连续批处理(continuous batching)分别优化什么?
  plain(66): 一项是在管理存储块，一项是在安排不同长度的请求进出。空位利用更灵活不意味着所有瓶颈消失，模型计算、网络、访存和工作负载仍会影响效率。
  pitfalls: ["分页后所有内存问题都消失。", "把示例共享比例泛化为固定性能收益。"]
======AG-005 Agent 的记忆怎么做?短期记忆、长期记忆、任务状态分别存在哪?
  plain(67): 历史档案、当前桌面上展开的资料、长期索引与任务进度表不是同一个东西。档案保留下来不代表每次都能摊开读完，长期保存也不等于内容永久正确。
  pitfalls: ["把短期记忆等同全部上下文窗口。", "把向量化所有聊天当成可靠长期记忆设计。"]
======LP-005 LLM 流式输出有哪些实现方案?SSE、WebSocket、轮询该怎么选?
  plain(69): 先区分“传什么格式”和“用什么客户端读取”。网络收到的一块数据不一定是完整事件，更不一定对应一个token；应用仍需维护消息和任务的边界。
  pitfalls: ["把网络chunk当成完整事件。", "把WebSocket全双工当作自动可靠恢复。"]
======FD-017 『预训练目标(下一 token 预测)』为什么能涌现出推理等复杂能力?
  plain(79): 学会接续许多不同文本，可能同时学到语言、模式与部分任务规律；能续写并不自动等于理解所有事实。这个直觉帮助解释为何会有迁移，不能当作保证任意复杂推理出现的定理。
  answer(117): 预测下一token会促使模型学习有助于解释数据的统计结构，训练后可能在多种任务上表现出迁移能力。但这不是完整能力机制已经得到证明，也不意味着数据覆盖到哪里能力就必然到哪里。数据、架构、优化、规模、后训练和推理使用方式都会影响观察结果。
  pitfalls: ["把直觉解释写成已证明的完整理论。", "把流畅答案或数据覆盖当成全部能力保证。"]
======AD-014 开源推理引擎(vLLM/SGLang/TensorRT-LLM)的选型考虑有哪些?
  plain(76): 可以把引擎当不同的执行系统：接口外观相近，内部排队、缓存和算子路径仍可能不同。旧能力表会过期，应该用自己需要的功能做小规模合同测试，而不是只看名字排名。
  pitfalls: ["用旧表格的❌代替当前功能核查。", "只凭框架名称承诺最高性能或透明切换。"]
======AD-001 微调(fine-tuning)和 RAG 怎么选?LoRA 是什么?
  plain(85): 可以把RAG看作答题时查资料，把微调看作改变答题习惯和能力。查到的资料也可能错，训练也不保证背住新事实。这个类比只说明信息进入系统的位置，不代表两种方法在能力上完全互斥。
  pitfalls: ["把RAG和微调划成永不重叠的能力边界。", "将某个实验的参数比例或显存节省当作所有模型保证。"]
======AD-002 量化(quantization)和 KV Cache 是怎么把大模型塞进普通显卡的?
  plain(64): 先区分“东西怎样压缩存放”和“哪些旧结果可以重复利用”。压缩后可能还要解包，保存历史也会占空间，因此省字节与提速不是同一个保证。
  pitfalls: ["按INT8、NF4、FP8名字排成统一精度阶梯。", "把KV节省和权重量化节省混成同一数值。"]
======FD-024 模型的『上下文学习』(in-context learning, ICL)是什么?为什么不用训练就能学新任务?
  plain(73): 把规则和例子放在当前试卷上，模型作答时可以参考它们；这与把知识永久训练进参数不同。关键是示例是否继续作为输入，而不是用户是否点击了“新会话”按钮。
  answer(113): 上下文学习通常指推理时通过指令和示例影响当前任务表现，而不更新模型参数。示例怎样起作用仍有不同研究解释，不应把任务定位等某一假说当定论。能力取决于任务、示例和模型；既不能保证任意新任务都能学会，也不能断言所有未见任务都不可能。
  pitfalls: ["把一种ICL理论解释当唯一已证机制。", "把某任务上有限示例的效果泛化为任意任务能力。"]
======FD-026 KV Cache 是什么?为什么它让长对话越来越贵?
  plain(80): 缓存像保留已经做过的中间工作，下一步少重做，但仍要参考越来越长的历史。分页、量化、滑窗和压缩解决的约束不同；有些会改变可用上下文或保真边界，不能一概当无损加速。
  pitfalls: ["用Q头数估算GQA缓存。", "把理想KV载荷当作模型完整显存，或混用GB与GiB。"]

======AG-010 LangChain / LlamaIndex 这类框架的价值和边界是什么?什么时候该裸写?

把提示、检索参数、预算和错误路径显式化；锁版本并验证实际使用的接口，不能由“统一API”推出所有模型可无损互换。

======AG-011 怎么把内部系统能力封装成一个 MCP 服务器?写一个最小实现需要什么?
  plain(88): SDK可以减少协议收发代码，业务处理仍要自己负责。stdin/stdout并不意味着没有序列化或安全风险，远程HTTP也不等于浏览器EventSource就是完整MCP客户端。

======FD-007 长上下文的注意力变体(MQA/GQA/FlashAttention)解决什么问题?了解常识即可的三个名词。
  plain(72): 一项是在减少要保存的历史份数，一项是在改变计算时的数据搬运方法；它们不是同一本账。少搬运不意味着所有乘加消失，也不保证任意模型无需适配就能采用。
  pitfalls: ["把KV容量、注意力矩阵和计算时间混作一个指标。", "把数学精确等同浮点逐位一致。"]
======AD-003 PPO 和 DPO 是什么?概念层面的区别与取舍。
  plain(79): PPO像在尝试过程中根据评分调整策略，DPO像拿成对结果学习哪种更被偏好。类比不能推出偏好一定来自人工，也不能推出DPO每一步都会让每个好答案的绝对概率上升。
  pitfalls: ["把相对偏好优化说成所有绝对概率都单调变化。", "按模型角色数直接推断资源倍数。"]
======AG-015 ReAct 和 Plan-and-Execute 两种 Agent 范式有什么区别?各适合什么任务?
  plain(70): 一种做法是逐步探索，一种是先列里程碑再推进；二者都可以回头修正。重要的是执行后观察到什么、为什么换路，而不是是否把文字标签叫Thought。
  deep tail(185): …多轮重发历史、模型分层、摘要和缓存共同影响费用。固定每轮增长c且全部重发时，累计输入是cn(n+1)/2，不是指数增长。
  pitfalls: ["ReAct无回看或修正能力。", "某种组合必然降本70–90%。"]
======AG-016 Agent 的反思(reflection)模式是什么?什么时候值得多花这一轮?
  plain(66): 让作者自查有帮助，但自查者可能重复同一个误解。给出一条能验证的失败证据，比笼统要求“认真检查”更具体；换模型也不能自动消除共享偏差。
  pitfalls: ["检查次数越多质量必然越高。", "把批评文本当作真值或执行凭证。"]
======AG-018 自研 Agent 怎么作为 MCP 客户端接入外部工具?宿主侧要处理什么?
  plain(66): 接入需要确认对方提供什么、当前主体可以用什么，以及如何把请求和结果接进自己的程序。模型擅不擅长选择工具与协议能不能连通，是两种问题。
  answer(115): MCP宿主负责连接或请求管理、能力发现、适配、调用转发和生命周期治理。模型接口与MCP之间的映射是宿主策略，程序也能直接调用MCP。具体初始化和会话头按版本实现；以下以2025-11-25为例，不能把它的会话模型套到所有未来版本。
  deep tail(197): …

### 升级与故障
工具清单变化、断线、超时、取消和结果未知均需按所用协议与业务契约处理；重试写操作前核对实际结果。
  pitfalls: ["把原生FC当协议运行前提。", "认为连接断开就能确定服务端已停止副作用。"]
======AG-019 MCP 服务器的三类原语里,resources 和 prompts 什么场景用?和 tools 怎么配合?
  plain(79): 一份政策可按URI取，也可以通过带参数的查询工具取。选择形式取决于寻址、发现、参数和使用方式，不取决于它是否一定修改文件。模板提供做事提示，不能自行授予权限。
  pitfalls: ["Tool必然写入外部世界。", "把原语控制方式当作权限保证。"]
======AG-022 LangGraph 式『图编排』是什么概念?和代码写流程相比取舍是什么?
  plain(79): 流程图像明确标出每步读取什么、写回什么和下一步去哪。恢复是根据保存的状态重新推进程序，不是冻结了整个进程内存。图能帮助组织复杂流程，但不会代替权限与业务核验。
  pitfalls: ["配置了图就自动有持久化与exactly-once。", "认为普通调试工具全部失效。"]
======FD-010 MoE(混合专家)是什么?为什么它能『大而不贵』?
  plain(69): 像有多个可选处理分支，每次只调用部分分支，但分派、搬运和等待也要时间。这个比喻不说明专家一定具有清晰的人类学科分工，更不提供固定速度比例。
  answer(112): MoE让路由为每个token选择部分专家参与计算，因此总参数与激活参数是两种口径。它可以用稀疏激活扩展容量，但延迟还受路由、负载、访存、通信和硬件布局影响。激活参数相同不代表速度等同某个稠密模型，也不能把总参数直接当知识量。
  pitfalls: ["激活参数=同规模稠密模型速度。", "auxiliary-loss-free=任何均衡辅助项都不存在。"]
======FD-012 解码策略全景:greedy、beam search、top-k、top-p 各是什么?LLM 为什么基本不用 beam search?
  plain(73): 贪心每一步只看当前最优选项；beam暂时留几条路，但丢掉的路也可能后来更好。采样给不同路径机会。这个类比不能推导哪条结果真实正确，还需要任务验证。
  pitfalls: ["把高概率、全局最优与事实正确当成同一件事。", "声称beam不能复用KV缓存。"]
======FD-013 预训练和后训练(SFT/RLHF)的数据有什么不同?为什么数据配比决定模型性格?
  plain(84): 预训练和后训练像通识积累与后续专项训练，但专项训练不只改格式，也可能改变任务能力和事实表现。它与检索提供新证据是不同途径，不能用这个类比证明谁只能学知识、谁只能学行为。
  answer(108): 预训练通常从大规模数据学习表示和生成规律，后训练指在其后进行的适配与对齐，SFT也属于后训练。示范、偏好优化、奖励优化和拒绝采样可以采用不同组合并迭代。具体模型的训练配方是实例，不是所有模型必须依次经过的三阶段定律。
  pitfalls: ["把post-training排除SFT。", "把一个模型报告的流程当成所有模型必经阶段。"]
======FD-014 Scaling Laws(缩放定律)的常识:参数、数据、算力怎么换算『能力』?
  plain(73): 它像一张限定实验条件下的投入产出趋势图，能指导候选配置，但不保证换一个任务仍按原比例提升。考试过线这样的离散指标也可能让平滑变化看起来像突然出现。
  answer(115): 缩放律描述特定训练设置中损失与参数、数据、计算的经验关系，不是把模型参数换算为业务能力百分比的公式。固定训练算力的优选点还会受到推理成本和部署目标影响。所谓涌现也需检查任务、模型、样本与评价指标，不能仅凭一条曲线推断完整能力机制。
  pitfalls: ["把loss改善直接写成业务收益保证。", "把某个实验比例当永久行业标准。"]
======LP-001 temperature 和 top_p 到底在控制什么?什么任务该调高、什么任务该调低?
  plain(64): 先改变候选分布，再选择考虑的候选集合，和真正保证事实正确是不同问题。降低随机性可能改变一致性，但不会自动修复错误知识或任务理解。
  pitfalls: ["所有推理任务统一T=0。", "固定seed保证任意设备和版本一致。"]
