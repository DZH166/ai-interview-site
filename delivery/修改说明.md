## 第一阶段:数据可靠性与页面生命周期(A 组)

### A1. 所有导入入口共用校验,启动隔离坏数据
- **共享校验下沉数据层**:`Store.validateQuestion / validateQuestions`(store.js)成为唯一 schema 规则(字段类型/数组/枚举/嵌套/编号/乱码/来源格式;`tags` 必须是非空字符串数组——报告的 `tags:"Python"` 用例在此被拒)。维护页题库导入、资料备份、完整备份、启动读取全部走这一份规则;视图里的本地副本删除。
- **备份入口全有全无**:`importLibrary` 先整体校验(含版本检查 v≠1 拒绝、`aiiv-full` 误入拒绝并指引),任何一题/一篇资料不合法 → 整个文件拒绝、存储快照不变(浏览器实测:报告原用例 0 写入)。
- **启动隔离**:坏扩展数据不再进入内存,原始内容保留在 `aiiv:quarantine` 键(不删不清);合法部分照常加载。浏览器实测:storage 里塞 1 坏 1 好 → 刷新后站点正常、坏题消失、好题保留、维护页出现「历史坏数据已被启动隔离」提示和「导出隔离数据」按钮(原始 JSON 可拿去修复)。
- 验收对照:上述坏文件、未知版本、只有 ID 的题/资料、同批重复 ID 均有明确错误且快照不变(行为测试 13 项新断言 + 维护页真实入口实测)。

### A2. 快速结束不丢答案、草稿不复活
- 所有离开当前题的动作(下一题/上一题/对照/复盘/结束/完成/放弃/路由离开/pagehide)**先同步捕获输入框内容**再切换(captureInput,不经防抖)。
- 防抖回调绑定会话 ID;会话终结(endSession:完成/放弃/开新一轮)后 `state.ended` 置位,旧回调不得写回;新一轮开时作废旧会话。
- 笔记同生命周期问题一并修:App.route 离开任何视图前先 flushNote(路由切换时输入框还在,同步落盘),不再只靠 pagehide。
- 浏览器实测:输入「快速结束时写下的最后答案」→ 立即点结束 → 该答案完整进入历史轮次;等超过防抖时长草稿仍为 null(不复活);正常 5 题自测与定向复习不受影响。

### A3. 完整备份一次完整恢复 + 明确清空语义
- 新增 `Store.importFull` 与维护页「导入完整备份」按钮:预览(记录/轮次/草稿/导入题/资料数量+合并规则)→ 整体校验 → 三个存储键按序原子写入(后写失败回滚先写)→ 成功后重建内存与索引。一次恢复全部承诺数据。
- 「导入记录」「导入题库与资料」入口遇到 `aiiv-full` 明确拒绝并指引走完整入口(反之亦然)——不再有"拆成两个秘密操作"。
- **清空语义**:备份字段「明确存在」且备份更新 → 采用备份值(含空串/false,即恢复被清空的笔记/状态/收藏);字段缺失 → 不动;旧备份(无时间戳)→ 只补空不覆盖;未采用的数据不提升时间戳。浏览器+行为测试均覆盖(更新备份清空笔记生效 / 旧备份不清空 / 取消收藏可恢复)。

### A4. 路由退出统一清理
- App.route 渲染新视图前统一执行:flushDraft(自测输入)→ flushNote(笔记)→ DocsView.cleanup(按真实滚动位置保存文档位置、作废令牌、注销 window scroll 监听)→ StudyView.cleanup(键盘监听)。
