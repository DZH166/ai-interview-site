# 问答界面一次性展开:融合答案卡 + 默认展开

2026-09-16。用户反馈:问答界面每个区块都要点开才能看到,希望「直接显示一版答案和面试表达的融合」,
其余大白话/原理/例子/追问/误区系列也一次性铺开。

## 改了什么

| 项 | 改动前 | 改动后 |
|---|---|---|
| 答案与面试表达 | 两个独立区块,默认收起 | 合成一张「答案与面试表达」卡,默认展开,内部仍分「直接答案」「面试表达 · 口述版」两个小标题 |
| 其余区块 | 大白话/原理/例子/面试表达/追问/误区/理解检查/出处,共 9 块全收起 | 去掉重复的独立「面试表达」块,其余 7 块默认展开 |
| 自测场景 | 默认收起天然支持先自测 | 新增「只看题干」按钮:一键收起全部答案与解析,保留先自己答一遍的用法 |
| 区块清单 | 学习页与浏览详情各写一份,易漂移 | 统一由 `QRender.standardSections(q)` 生成,两处共用 |

浏览详情(`#q-detail`)与完整学习页(`#/study/`)同步生效。打印样式仍强制展开全部区块。

## 为什么留一个「只看题干」

改动前「答案默认收起」不是随手写的:浏览器测试里有两条断言专门守着
「题干始终可见、答案展开前不可见」,目的是让人先自己答一遍再看参考。
这次按用户要求把默认态倒过来,但**没有把那个能力删掉**——`只看题干` 一键回到旧行为,
并且这条路径也进了断言。默认态是偏好,自测能力是功能,两者不冲突。

## 测试

新增/改写的断言,全部用 `git worktree add <dir> HEAD` 在**改动前**版本上反向验证过:

- `tests/browser/pi-agent.js`:15 条在改动前版本失败(融合卡默认可见、两段分列、
  只看题干收起、五条评分标准随融合卡可读、单块仍可手动折叠与展开)。
- `tests/browser/ai-series.js`:4 条在改动前版本失败(无需点击即可见、两段分列、
  融合补充可直接读、所有区块到达即展开)。

反向验证做法:worktree 里把 `check()` 临时改成收集失败(避免第一条失败就中断),
再逐条核对哪些断言在旧代码上会红——红了才说明断言不是恒真。
