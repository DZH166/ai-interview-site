# 阶段:SRS 间隔重复调度(2026-09-13,基线 8464079)

## 为什么做

「今日复习」此前只有手工状态:标「还不熟/待复习」的题永远在队列里,标「基本掌握」的题永远出去。
它能兜底,但记不住「什么时候该再看一眼」——这正是面试备考最需要的一层。

## 原则(先于实现定死)

1. **手动状态永远优先**:weak/review 的题始终进手动队列,不看排期;算法只产生「建议」,
   单独一节展示,可以无视,绝不改变任何题的状态。
2. **重复点击同一状态不推进排期**:浏览/学习页的状态按钮是标记不是练习;
   唯一例外是模拟面试的复盘标记——那是真实练习信号,带 `reschedule` 显式重排
   (否则「到期建议」里的题标「基本掌握」后永远出不去)。
3. **状态清空 = 撤出建议**:`setStatus(qid,'')` 与「备份清空状态」都会连带清掉 srs。
4. **不猜映射**:专项尝试的自评(solved/partial/unsolved)归属 drillId,与题目没有稳定映射,
   本版不参与排期,如实不做。
5. **没有排期的题永远不产生建议**:`SRS.isDue` 对缺字段/坏字段一律返回 false,不猜。

## 实现

| 落点 | 内容 |
| --- | --- |
| `app/js/srs.js`(新) | 纯调度模块,SM-2 简化:again(归零+遗忘+ease-0.2)/ hard(×1.2)/ good(streak 第1次1天、第2次6天、之后×ease)/ easy(×ease×1.3);ease∈[1.3,2.8],ivl 上限 180 天。自包含,Node 可测 |
| `app/js/store.js` | `setStatus` 是唯一排期入口(状态变化或显式 reschedule 才排);`validateRecordsObj` 接受 srs(数字字段+lastRating 枚举);合并规则:srs 整份随 `_updatedAt` 走,状态被备份清空时连带清;`MAX_ROUNDS=100` 常量(修掉完成轮次截 50 / 备份合并截 100 的不一致——两处各写一个数字迟早漂移) |
| `app/js/views-review.js` | `getDueSuggestions()`(排除 weak/review,不与手动队列重复)与 `getTodayOverview()`;今日页新增「到期建议」卡片,每题两个出口:「还记得」(重排到下一轮间隔,状态不变)/「忘了」(转还不熟,回手动队列) |
| `app/js/views-knowledge.js` | 工作台首页「今天的三件事」第一件改用 `getTodayQueue()+getDueSuggestions()` 同一口径,注明「可无视」 |
| `app/js/views-practice.js` | 模拟面试复盘标记 `{reschedule:true}`;完成轮次上限改用 `Store.MAX_ROUNDS` |
| `app/js/common.js` | 学习页/浏览页记录栏只读提示「🔁 建议:明天/N 天后」 |
| `tools/build.py` + `app/sw.js` | srs.js 进盖章清单与 APP_SHELL(否则离线用户加载不到该模块) |

## 诚实边界(未做)

- 专项自评未接排期(映射不稳定,不猜);
- 未做真实设备长周期验证(间隔增长曲线是数学断言,不是月级实证);
- FSRS 等更现代算法未引入——SM-2 简化版的参数少、可解释,符合「建议可无视」的定位。
