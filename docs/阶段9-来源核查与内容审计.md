# 阶段9:来源核查与内容审计

日期:2026-09-11。全部结论由脚本真实执行产生,可用文末命令复跑。

## 1. 把「已核验」从一句话变成可复跑的证据

之前 `data/sources.json` 里写着「所有来源均于 2026-09-06 实际访问核验」——
这是一句**无法被检查**的声明。本阶段新增两个工具,把它变成可复跑的动作。

### tools/verify_sources.py

1. 从 `data/sources.json` 与全部 `data/questions/*.json` 收集所有唯一链接,
   并记下每个链接被谁引用(来源表条目 / 具体题号)。
2. 逐条真实 GET(跟随跳转),记录状态码、最终地址、耗时。直连失败自动退到本机代理。
3. **不只看状态码**:能打开但指向别的东西,是比 404 更隐蔽的错误。
   - arXiv abs 页 → 回读页面标题,与题库声明的论文标题比对;
   - GitHub 仓库 → 回读仓库名,与声明比对。
4. 输出 `docs/来源核查-<日期>.md` 与 `delivery/来源核查.json`。

### tools/content_audit.py

按固定阈值查十要素完整性、引用完整性(related / prerequisites / doc_refs
/ 学习路径阶段的题目与文档)、核查状态合法性、占位符残留、数字型断言。

## 4. 工具自身的两处误报(已修,并加了自检)

首轮报出来的问题里,大部分**不是数据的问题,是检查器的问题**。
这类「工具造假」如果不修,后面所有结论都不可信。

| 误报 | 真因 | 修法 |
| --- | --- | --- |
| 19 条「论文标题与声明几乎不重合」 | 页面标题其实全对。声明的 `name` 有两种写法:「论文 · Attention Is All You Need (NeurIPS 2017)」和简写引用「BERT(Devlin 等 2018)——encoder-only 双向预训练」。旧逻辑按分隔符取「——」后半段,取到的是中文说明 | 改为三层判断:标题词重合度(双向取大)+ 声明的作者/会议是否出现在页面 + 都不成立才叫可疑 |
| 3 条「疑似占位符」 | `XXX(违禁品)` 是脱敏写法、`待补充` 是业务语义、`appendToDOM` 里含 `toDO` | 占位符改为按整词匹配(`\bTODO\b`),并显式列出豁免规则与理由 |

两个工具都加了 `--selftest`:

- `verify_sources.py --selftest`:5 组正反例 + 1 组「简写引用不该被误报」的不变量。
- `content_audit.py --selftest`:4 个真占位符必须命中,4 个正常写法必须豁免。

**自检的意义**:把检查器放松之后,必须还证明它抓得住差错,否则「0 问题」只说明它坏了。

## 5. 内容审计结论

- **硬问题 0 条**(306 题)。
- 修掉 1 条真实的交叉引用错误:**AD-023 的 `related` 指向了自己**,
  已换为 AD-022(合成数据质量,与「数据多样性」同主题、不同题)。
- 「内容偏薄」的阈值原来拍在 150 字,连报 6 条,而那 6 题的 `deep` 都在 500 字以上
  ——**阈值噪音**。改为两层:
  - 绝对下限(拦「一句话打发」):answer 120 / plain 100 / deep 200 / example 60 / interview 120,总长 800。
    取值依据是题库真实最小值(answer 125 / deep 235 / 总长 885),留在最小之下。
  - 相对偏薄:总长低于全库 5% 分位(1241 字)。这是**排序信息,不是缺陷**
    ——任何题库都有最薄的 5%。列出来供参考,不当问题。
- 占位符残留:0 条(3 条误报见上)。
- 核查日期过期:0 条。

### 数字型断言清单

筛出「可被面试官追问的量化说法」(百分比 / 倍数 / 万·亿·M / 年份 / token),
排除带保留词(约、通常、量级、取决于……)的软说法后,有 **31 道题**存在
3 处以上硬量化说法、且没有一手来源页。

逐条看下来,这些**绝大多数是设计示例与自洽算式**,不是对事实的断言,例如
Agent 上下文预算画像(32K 里 system 2K / 工具结果 12K)、灰度比例(1~5%)、
影子流量采样(10~50%)。这类数值是「我的设计选择」,不需要外部来源。

对其中**可验算的算式**做了抽样复算(EN-009):

| 题目里的说法 | 复算 | 结论 |
| --- | --- | --- |
| 99.9% 可用 → 全年不可用 <8.8 小时 | 365×24×0.001 = 8.76 小时 | 一致 |
| 50 QPS × 3500 token = 175K token/s | 175,000 | 一致 |
| 175K × 60 = 10.5M TPM | 10,500,000 | 一致 |
| 10.5M ÷ 80K ≈ 131 账号 | 131.25 → 向上取整 132 | 一致 |
| 10K TPM ÷ 2K token = 5 请求/分钟 ≈ 0.083 QPS | 0.0833 | 一致 |

清单本身保留在审计报告里,供逐条复核,而不是当作「已通过」。

## 7. 复跑方式

```bash
python tools/verify_sources.py              # 联网逐条核验,写报告
python tools/verify_sources.py --selftest   # 只跑比对逻辑自检(不联网)
python tools/content_audit.py --report      # 内容审计并写报告
python tools/content_audit.py --selftest    # 检查器自检
python tools/content_audit.py --list-nosource
```

`verify_sources.py --strict` 在出现真失效链接时以非 0 退出,可接入定期检查。
