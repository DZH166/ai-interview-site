| 问题 | 原因与最终行为 | 验证 |
| --- | --- | --- |
| 搜索跳转已高亮却看不到正文 | `content-visibility: auto` 的离屏布局影响锚点位置及可见文字。仅对跳转目标先完成布局，再定位与高亮；保留其他章节的按需布局。延迟回调同时核对路由、渲染代次及容器连接状态。 | 原 `ai-series` 的真实搜索点击断言保持；新增 `study-anchor` 检查 1200/360px 的到达时刻及连续六帧，另查迅速离开后不能滚动或高亮新题。修复前可复现失败。 |
| 已有用户首次刷新混用新数据与旧脚本 | 旧 Service Worker 缓存未版本化脚本，新入口却采用新版资料清单。构建为 17 个脚本/样式生成内容版本 URL，并让预缓存使用完全相同的 URL；版本化资源缓存保持内容稳定。 | `sw-upgrade` 从 Git 读取真实旧 main 页面及 worker，在同一站点子目录安装后升级。旧 worker 继续控制时，首次刷新即可读新版文档；随后新 worker 接管、旧壳清理、离线题目与文档可用，笔记、收藏、未完成回答保留。14 项断言通过，修复前正文为空且新版加载接口缺失。 |

构建先计算各资源内容版本，再计算应用壳缓存版本，避免循环依赖。两次本地构建的 **29 个生成文件逐字节一致**；云端重新构建也未产生差异。缓存检查包含入口和 manifest，版本查询参数不再漏计首题资源大小。

本地还重新执行全部 34 个单元套件和 8 个重点浏览器套件；最终以云端全部 77 个套件为功能验收依据。旧 worker 测试等待新 controller 真正到达 `activated`，再断言旧缓存清理完成，避免把 `controllerchange` 误当作激活工作已经结束。
