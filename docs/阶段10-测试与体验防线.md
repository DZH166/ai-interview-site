# 阶段10:测试与体验防线

日期:2026-09-11。核心原则:**先写测试量出现状,再动实现,最后用历史版本反向验证断言非空。**

## 1. 顺序为什么是这样

如果先改代码再补测试,「测试通过」只说明测试和代码互相迁就。
本阶段的做法:

1. 先写 `tests/browser/a11y-360.js`,在**未修任何代码**的当前版本上运行;
2. 把测试文件复制进一个 `git worktree`(指向 HEAD),在**修复前**的代码上再跑一次;
3. 只有「修复前失败、修复后通过」的断言才算数。

第 2 步的结果:**修复前 21 通过 / 13 失败**。这 13 条失败就是这次要修的真实缺陷。
没有这一步,后面所有「全绿」都不值得信任。

## 2. 修掉的 8 个体验缺陷

### 2.1 窄屏(360px):没有发现问题

九个路由(首页 / 路径 / 练习 / 文档 / 自测 / 复习 / 维护 / 搜索 / 学习页)在 360×640 下
`scrollWidth` 全部等于 360,**无横向溢出**。这条防线现在是常驻的:
溢出时报出具体是哪个元素越界,而不是只说「溢出了」。

### 2.2 全局骨架缺的无障碍语义

| 缺陷 | 影响 | 修法 |
| --- | --- | --- |
| 没有「跳到主内容」链接 | 键盘/读屏用户每次都要 Tab 过 7 个导航链接 | 加 `.skip-link`,聚焦时从视口上方滑出;`<main>` 加 `tabindex="-1"` 作为落点 |
| 导航没有 `aria-label` | 读屏只报「导航」,多个导航区无法区分 | 加 `aria-label="主导航"` |
| 当前页只有视觉高亮,没有 `aria-current` | 读屏完全感知不到「你现在在哪一页」 | 路由切换时同步 `aria-current="page"` |
| 主题按钮只有 emoji + `title` | emoji 无字面语义,读屏读不出「切换到暗色模式」 | 加 `aria-label` 与 `aria-pressed`,随主题状态更新 |
| 全局搜索框只有 placeholder | placeholder 不是标签,读屏可能读不到 | 加 `aria-label` |
| 提示条容器是**用到时才创建** | live region 必须在内容插入前存在,读屏才会播报——**保存成功/失败读屏全程静默** | 改为 `App.init` 时提前建好,标 `role="status" aria-live="polite"` |

`aria-current` 与提示条这两条是最容易被忽略的:它们不影响任何视觉表现,
只有用读屏或纯键盘操作才会暴露。

### 2.3 对话框的键盘可用性

原来的 `modal()` 有 `role="dialog"`,但缺四件事里的三件:

| 能力 | 修复前 | 修复后 |
| --- | --- | --- |
| 打开时焦点进入对话框 | ❌ 焦点还停在背景页面 | ✅ 焦点落到第一个按钮 |
| Tab 被圈在对话框内 | ❌ 第 1 次 Tab 就跑到背景的 textarea | ✅ 首尾循环,连按 12 次不跑出 |
| Esc 关闭 | ❌ 完全没处理 | ✅ 关闭 |
| 关闭后焦点回到触发按钮 | ❌ 焦点掉在背景控件上 | ✅ 回到「开始新尝试」按钮 |

另外补了 `aria-modal="true"` 和 `aria-labelledby`(指向标题元素,而不是写死的字符串),
关闭按钮补了 `aria-label="关闭"`。

实测差异(修复前的原始输出):

```
FAIL 连按 12 次 Tab 焦点始终留在对话框内(有焦点圈定)
  → 第 1 次 Tab 跑到了 textarea.path-drill-answer
FAIL Esc 能关闭对话框
  → {"stillOpen":true,"restored":false}
```

### 2.4 跳过链接不能破坏 hash 路由

本站用 hash 路由。跳过链接如果写成 `<a href="#view">` 并走默认行为,
`parseHash()` 会把 `view` 当成视图名 → 用户被带回首页。
所以点击时 `preventDefault()`,改为对 `<main>` 编程式聚焦。
这条也有断言守着(「跳过链接不会破坏 hash 路由」)。

## 3. 测试自身的两个缺陷(同样要修)

写测试时踩到两个坑,都属于「看起来在查,其实查不到」:

1. **合成键盘事件不能验证按键行为。**
   最初用 `dispatchEvent(new KeyboardEvent('keydown',{key:'Tab'}))` 测焦点圈定。
   合成事件不会触发浏览器默认的 Tab 移动,所以焦点永远「没跑出去」——
   这条断言在修复前也是 PASS,**是恒真的**。
   改成 Playwright 的 `page.keyboard.press('Tab')` 真实按键后,修复前立刻失败。

2. **元素缺失时测试崩溃,而不是报失败。**
   跳转链接的点击测试直接 `document.querySelector('#skip-to-main').click()`,
   在修复前元素不存在 → 抛 `TypeError` → 整轮测试中断,
   后面的断言一条都没跑到。改成返回 `NO_SKIP_LINK` 让断言正常失败。

第 1 条尤其值得记:一个恒真的断言比没有断言更危险,因为它会让人以为这里查过了。

## 5. CI 加固

`.github/workflows/validate.yml` 从 1 个 job 扩到 2 个:

- **validate**(18 步):新增回归测试、项目C 四层真实性、两个审计器自检、
  内容审计 `--strict`、来源结构检查;
- **browser**(6 步,新):安装 `playwright@1.61.1` + `npx playwright install --with-deps chromium`,
  真浏览器跑界面层回归与窄屏/键盘回归。

两个浏览器脚本原来把 Playwright 与 Chromium 的**绝对路径**写死在本机,
CI 上必然失败。现在改成:本地不设环境变量走机器上已装的一套;
CI 里 `PW=playwright CHROME=default` 走 Playwright 管好的浏览器。
