# 升级验收：项目证据材料与学习记录可靠性

基线：`cd986f4a942ffb0383a47110b602e1dbfe754656`。审查比较起点：`e0adacbf8e1e93c453bdad973ae7b5c1d90ed27e`。

本轮按用户新授权执行「先审查 → 确定方向 → 实现更新 → 验证 → 提交推送」。未操作真实浏览器学习数据；所有浏览器回归使用独立上下文与测试端口。保留静态架构、306 题、原有记录格式及模拟面试表达卡。

## 方向与交付

让用户把自己的项目验证过程带走,同时使保存、恢复和历史选择符合真实意图。具体交付：

- 独立的 30 秒、2 分钟口述文本,保留六段旧提纲。
- 当前口述选择依据的 runId；选择与文本共同自动保存、完整备份恢复。
- 项目 Markdown 与打印版 HTML；可导出选定运行,区分历史快照和当前口述。缺失证据报错,不会自动选另一条。
- 个人长文本在项目材料中完整保留；Markdown 里的代码、单引号、实体与链接语法按原文展示。
- 两种口述均进入全文搜索,命中后展开并聚焦对应字段；专项历史搜索显示选定快照。
- 同专项多份草稿可显式选择；提交后不会自动切换到旧草稿。
- 旧备份不能撤销较新笔记清空、状态重置与取消收藏；未编辑的初始记录仍可补入旧数据。
- 相同时间的历史按稳定身份排序；仅有自评也算有内容的草稿；未自评保持空值。
- 复习页将未选择评级的完成记录标为「未自评」；草稿和放弃记录的入口带具体身份,可以准确回到旧草稿或历史。
- 移除按运行条数鼓励成功经历的提示；首页只把本地当天实际写过回答的模拟轮次计为今日完成。
- 项目 C 通过摘录契约核对答案正文,保留独立 oracle 和生成器机制；原始候选答案可供定位。

## Standards

审查确认的三组问题已修复：

1. **题目清空复活**：旧 note/status/fav 的补值逻辑绕过更新时间。现在仅字段缺失或无编辑时间的初始值可补,较新明确清空保留。
2. **并行草稿自动切换**：完成最新草稿后,另一份更旧草稿自动进入编辑器。现在保留所有草稿,较早草稿需从提示中明确选择,不自动填回旧答案。
3. **虚构/丢失自评**：“提交后另开”默认填 unsolved,仅评级草稿又被当空内容删除。现在保留未自评,评级纳入内容判断并保留放弃痕迹。

实施后的独立复核另外发现项目 Markdown 的双重转义损坏单引号。已调整顺序,并使用 Markdown-it-py 真实渲染,比对引号、实体、反斜杠和代码原文,防止只靠字符串包含测试通过。

## Spec

对应上轮任务书的三个主要缺口已在本轮范围处理：

1. **C 引用标签被当成事实**：正确标签下的 30 天退款、定制商品可无理由退货,以及只有标签的答案曾被放行。现在每个候选分句须能从对应证据核对,多余主张和错误引用不能通过。
2. **口述与证据缺独立结构**：原来只有六段提纲及计时器。现在 short/long 分开编辑、选择证据、保存、搜索、导出、独立环境恢复均有实际操作验证。
3. **次数/旧历史暗示成果**：两条失败记录不会再被提示为可宣称成功；昨天的模拟历史不会将今天的任务标为完成。

专项历史的 `?at=` 也已补齐实际快照展示,避免只改变 URL 却展示当前编辑区。
