# 性能诊断补记 · 2026-09-29

本补记关联[工作台升级交付报告](工作台升级交付-2026-09-29.md)。目的为定位冷启动长任务；**以下九项均为单次诊断，不是正式五次验收，也不能用于宣称通过性能门槛。** 最终五次基线与候选结果以主报告及 `delivery/reviews/performance-*-20260929.json` 为准。

## 定位方法

使用隔离 Chromium 148、1280×900、CPU 降速 4 倍、下载 3 Mbps、上传 1 Mbps、100 ms 延迟，阻止 Service Worker。每项启动新浏览器和空白上下文，打开 `#/study/AG-001`；题面与笔记就绪后继续观察 1 秒，记录 Long Tasks。没有预热页面或读取个人浏览器数据。

通过 Playwright 响应替换分别试验图标、CSS 和分帧挂载，不把实验代码写入生产文件。响应替换会改变资源交付路径，因此本表就绪时间仅用于诊断，不与正式脚本结果直接比较。无业务脚本的“页面壳”和“单段中文”按文档加载完成计时，不与完整题目的就绪时间比较。

已有 Chrome trace 显示一次布局耗时约 2,043 ms，其中 104 次 `InlineNode::ShapeTextIncludingFirstLine` 累计约 1,792 ms；另有 SVG 文字图标的独立布局路径。Trace 开销明显，其数值仅用于归因，**不作为正式长任务测量**。可确认的热点是浏览器文本排版；首次字体初始化和回退的贡献仍是推断，未证明它是唯一原因。

## 保留与放弃

保留现有脚本 `defer` 和区块 `auto 220px` 策略。仅把 favicon 改成已有的 `icons/icon-192.png`（2,292 字节，已纳入离线缓存），与应用标志统一并移除 SVG 文字图标的额外排版路径；**不把这项改动描述为已解决长任务**。

不合入 650px 统一占位：例如“大白话”区块实际约 157px，过大占位会造成滚动几何变化。分帧原型虽拆散部分工作，整体就绪变慢且仍超限；字体和装饰字符实验没有稳定收益，也不合入。默认展开、输入控件、锚点和页面内查找语义保持原实现。

本轮未找到同时满足现有阅读交互和冷启动长任务不超过 200ms 的稳定最小改法。这是当前验收的真实未达标项，不等同于已经证明浏览器无法进一步优化。后续应结合正式五次结果与实机反馈，再评估更细的渲染分块；不得通过扩大占位、延后统计窗口或预热来制造达标结果。

诊断时使用 `output/playwright/layout-experiment.cjs` 和 `layout-{png,noemoji,large,paragraph,inherit,cjk,shell,minimal,progressive}.json`。这些是被 Git 忽略的本地排障产物；本补记已完整保留必要条件、数值与结论，不依赖这些文件才能理解结果。
