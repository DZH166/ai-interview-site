### 5.1 阶段8:项目C 四层诊断重建

职责分离是这次重建的核心:**运行侧只报现象,归因只发生在评测侧。**

| 层 | 谁来判定 | 判定依据 |
| --- | --- | --- |
| ① 库里没有 | **仅评测侧** `coverage_oracle`(人工标注) | 运行侧无权下此结论,拒答文案必须留悬置 |
| ② 检索没捞到 | 运行侧 `retrieve` | 零召回 / 强命中被裁掉 / 最高分不达标 |
| ③ 证据被预算截断 | 运行侧 `diagnose` | `truncated` 且存在被丢弃的强命中 |
| ④ 生成没守证据 | 运行侧 `validate(answer_text, hits)` | **按回答文本**判定,与故障怎么造的无关 |

- 固定唯一 `CONFIG = {top_k: 2, min_score: 2}`;四层在同一配置下**全部真实触达**,不再靠逐题手调阈值摆叙事。
- `EVAL` 评测集只放「标注 + 期望」,不含逐题阈值;未标注查询 `coverage_oracle` 会明确报错而不是猜。
- 第④层从 `broken_fake` 开关改成注入任意不守证据的生成器(`GENERATORS`),校验独立于故障来源。

缺陷状态(原 3.3 表):G-1 / G-2 / G-3 / G-4 / G-5 / G-6 **全部关闭**,
`tests/proj_c_layers_test.py` 每条都对应断言(含 G-0 检查器自检,防止又变成恒真断言)。

改名为**面试加油工作台**。起因是一个判断:本站此前只有「入口」和「过程」,
缺**出口**——用户写下的回答、笔记、专项尝试都留在站里,能导出的只有给电脑恢复
数据用的 JSON 备份,人拿着读不了、念不了。所以这次只做一件事:**把它变成能出东西的地方**。

| 变化 | 说明 |
| --- | --- |
| 首页 → 工作台 | 顶部直接给「今天要干的三件事」:复习队列、悬着的草稿与待消化专项、练一轮模拟面试;每件事带结论与入口 |
| 三件事的口径 | **复用** `ReviewView.getTodayQueue() / getDrillState()`,不在首页另抄一份(抄一份迟早两边不一致) |
| 出口:面试表达卡 | 新模块 `app/js/express.js`(纯函数,Node 可测),产出 Markdown + 打印版 HTML |
| 三处入口 | 工作台首页、模拟面试完成页、复习中心每一轮历史 |
| 内容来源 | 「我的回答」来自模拟面试记录;「我的笔记」来自题目笔记——**标签分开,不把笔记冒充成回答** |

诚实性原则(与本项目一致):

- 一轮里一题都没写回答 → **拒绝导出并说明原因**,不产出看着像材料其实空空如也的文件;
- 题库里找不到的题 → 跳过,不编造参考要点;
- 没做过模拟面试时,工作台上那个按钮**禁用并写明为什么**。

工程侧同时做了两件事:

- `app/js/express.js` 加进 `tools/build.py` 的盖章清单与 `sw.js` 的 `APP_SHELL`
  ——漏掉会导致**离线用户加载不到该模块**;并给 `shell-cache-stamp-test.js` 加了
  「app/js 下每个 js 都必须在上表里」的常驻断言(变异验证:拿掉即红)。
- 修掉 e2e 一个一直藏着的测试缺陷:`page.goto` 只改 hash 时**不会重新加载页面**,
  上一段留下的对话框会一直盖在页面上拦掉后续点击。此前几段只用 `evaluate` 读文本,
  所以没暴露;新增点击断言后立刻现形。已加 `closeAnyModal()` 并在导入段收尾关闭。

断言变化:`express-card-test.js` +40;e2e `25 → 46`。CI 的 `validate` job 增至 21 步。
