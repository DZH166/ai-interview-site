# 重点知识可视化:标注机制与首批精读

2026-09-16。用户要求把已经默认展开的正文里**重点知识用视觉方式突出**,并且要人工精读每一份答案后标出。
这是长跑工程,本文记录机制与第一小阶段。

## 做法:标注与原文分离

**不改题库原文**。题库上有三套东西会因改正文而惊动:内容审计的阈值、融合适配器的内容哈希守卫、
`content_version` 修订提示。直接往正文里插 `**` 或标记,这三套都会响,而且没法单独审「哪些是重点」。

所以标注单独存放:`data/highlights/<专题>.json`,每条记录 = 字段 + 级别 + 短语 + 为什么标它。
`tools/build.py` 合并进 `APP_DATA.highlights`,渲染时由 `app/js/highlight.js` 把短语包成 `<mark>`。

| 级别 | 含义 | 视觉 |
|---|---|---|
| `key` | 核心结论(面试必须说出口的) | 黄底 + 加粗 |
| `term` | 关键术语/机制名 | 蓝底 |
| `warn` | 易错点与红线(口径不能错) | 红底 |

## 三个必须解决的技术问题

1. **跨节点匹配**。markdown 会把 `**粗体**`、`` `代码` `` 拆成多个文本节点,按单个节点找不到短语。
   `highlight.js` 先把子树拼成一个长字符串定位,再按区间回切、分段包裹,所以跨格式的短语也能标上。
2. **重叠与重复**。渲染时后一条会被 `findFree` 跳过,等于白标。审计器把「同字段重叠」「完全重复」
   当**错误**处理,不是提醒。
3. **漂移**。原文一改短语就对不上。`tools/highlight_audit.py` 逐条核对短语是否逐字出现在该字段原文里,
   并禁止短语含 markdown 元字符(`*`、`` ` ``、`[]`、`_`、`|` 等,会被渲染吃掉)。

## 防「假通过」的验证

- **审计器自检**(`--selftest`,已进 CI):7 个用例——好标注放行 + 6 类坏标注(对不上原文、含元字符、
  重叠、重复、级别非法、字段非法)必须全部命中。
- **真实数据注入**:往 `fundamentals.json` 里塞「短语对不上原文」和「级别非法」各一条,
  审计器报 2 错并 `exit 1`;还原后回到 0 错。证明它不是空转。
- **浏览器逐条命中**(`tests/browser/highlight.js`,12 条,已进 CI):不是「页面有没有 mark」,
  而是要求 `applied === expected` 且 `missing` 为空——漏标、对不上、被 markdown 吃掉都会红。
  另断言未标注的题**一个 mark 都没有**(防误伤)、三种级别的底色互不相同、`key` 加粗而 `term` 不加粗、
  360px 不横向溢出。
- **两处定向注入**(证明断言有牙):把答案两段改回不套标注 → 「study page shows the marks」红;
  把 `term` 的底色改成与 `key` 相同 → 「三种级别底色互不相同」红。

  第二处一开始**没抓到**:原断言把底色与字重拼成一个字符串比较,底色改成一样、只有字重不同就蒙混过去了。
  拆成「底色互不相同」+「key 加粗而 term 不加粗」两条后才抓住。这条记录在这里,是因为它正是「弱断言」的典型。

## 密度:第一版被自己打回

标完首批后截图自审,发现 FD-005 的答案段落里黄色占到近一半——**满屏黄等于没有重点**,重点就不再"重"了。
这不能靠肉眼逐题判断,于是给审计器加了可量化的密度规则:

> 单个字段被标中的字数占比 ≥ 35% 报警,≥ 50% 报错。超限要**回去删条**,不是放宽阈值。

规则一上,首批 5 题立刻查出 2 处错误 + 2 处偏满:

| 题 | 字段 | 标中占比 | 处置 |
|---|---|---|---|
| FD-003 | answer | 92% | 重标:4 条短句,训练/推理的对照移到 interview |
| FD-004 | answer | 59% | 重标:3 条,只留两条原则 + judge 偏差 |
| FD-002 | answer | 46% | 重标:3 条,根因改用短说法,定义让位 |
| FD-005 | answer | 47% | 重标:3 条,定义句去掉(标题已经在问定义) |

重标后 49 条、0 错 0 警,截图复核黄底约占四分之一,重点能一眼抓住。
**结论:篇幅有限时不是删要点,而是把长句压成短句**——比如把 41 字的根因压成 20 字,信息还在,视觉负担减半。

## 已知取舍

- 单题标注上限 12 条(超出报警)。重点太多等于没有重点;超限时要回去删,不是放宽阈值。
- 标注只在学习页与浏览详情的正文生效,不参与搜索索引——搜索索引吃的是原文,这点没动。
- `example` 字段带代码块时标注要避开代码内容(含反引号会被审计器拦下),所以 code 类题的重点
  更多落在 `answer` 与 `deep`。

### 一个真实回归:测试自己的假设过期了

题标到 100% 那一刻,`tests/browser/highlight.js` 直接崩:

```
TypeError: Cannot read properties of undefined (reading 'id')
    at Object.mdField (app/js/common.js:182)
```

根因不在标注数据,而在**断言的前提没了**。原断言是:

```js
Data.allQuestions().find(x => !ids.includes(x.id))   // 找一道"未标注的题"
```

题库里已经没有未标注的题,`find()` 返回 `undefined`,`q.id` 就炸了。
这正是「断言依赖外部数据快照」的典型失效方式:数据覆盖率一变,断言就从"能证明"退化成"根本跑不起来"。

**修法不是删断言,也不是退化成"如果找不到就跳过"**(那会让这条保障永久失效)。
改成**差分探针**,同一段正文挂两个题号:

| 探针 | 期望 | 证明了什么 |
|---|---|---|
| 真题号(`AD-001`) | mark > 0 | 正对照——否则"哪儿都没 mark"也能蒙混过关 |
| 幽灵题号(`ZZ-000`) | mark == 0 | 标注按题号精确匹配,不误伤 |
| 若将来又有未标注题 | mark == 0 | 顺带守住(报告里带 `LEAK:` 前缀) |

三半合并在**一条**断言里,断言总数恒为 12,不随题库覆盖度漂移。

**反向对照(变异测试)确认它有牙**——在独立 worktree 里注入两个变异,新断言都红:

| 变异 | 结果 | 关键点 |
|---|---|---|
| `renderField` 直接返回原 HTML(完全不标注) | 红:真号 0 个 | **旧的"未标注题无 mark"断言在这个坏版本上会通过** |
| `spansFor` 未知题号兜底全库标注 | 红:幽灵号 7 个 | 只有差分探针才抓得到 |

第一行是这次最值钱的结论:老的断言形态在"渲染彻底坏掉"时是**绿的**,新的差分形态才区分得开。


### 并行推进时踩的坑(2026-09-16 晚)

剩余题量太大,改成**按专题拆 5 个并行 worker**。结果 3 个被账号频率限制(429)中断,
其中 llm-prompt 恰好死在批量修错那一步,残留 5 错 7 警——**残留错误会压住整库的 `--strict`**,
后续所有校验都是红的,必须优先清掉。

处置:把受影响的 5 道题**整题重标**(而不是从错误堆里挑补丁),顺带把密度问题一起解决。

教训:
- 同模型并行的 worker 数别超过账号额度,5 个会打满配额;压到 2~3 个或错峰。
- worker 的产出要当**半成品**审,它的 `--strict` 未必跑完。
- 主会话模型与 worker 默认模型不同,worker 被限流时主会话仍可继续干活——这是兜底路径。

推进方式固定为「读全文 → 写标注 → 跑 `highlight_audit.py --strict` → 修」,
每批 2~3 题;密度与命中都过了再提交。查进度 `python tools/highlight_audit.py`,
列待办 `--list-todo`。

写作流程用 `tools/_merge_highlights.py <专题> <批次.json>` 合并(拒绝覆盖已有题号,
避免手滑冲掉既有成果)。

### 写作时反复踩到的四类坑(校验器每次都能抓到)

| 类型 | 实例 | 对策 |
|---|---|---|
| 抄错原文 | 「而非把DPO…」写成「不能把DPO…」;跨括号取串 | 写完整字段名 + 跑 `--strict` |
| 含 markdown 元字符 | `create_agent` 的下划线、`>阈值` 的尖号、`**重现**` 的星号 | 换同段无元字符的短语 |
| 字段挂错 | 短语其实在 `deep` 里,却写成了 `example` | 报错信息会指出字段 |
| 密度超限 | 短答案段(120~160 字)标 3 条就过线 | 压短长句,不删要点 |
