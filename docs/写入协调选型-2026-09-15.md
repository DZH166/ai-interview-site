# 写入协调方案选型(2026-09-15,任务书「后续2」)

## 候选比较

| 方案 | 优点 | 否决/采纳理由 |
|---|---|---|
| **异步协作锁(Web Locks)** | 跨页互斥彻底 | 否决:①需迁移全部 13 个依赖 `saveNow()` 同步返回值的调用点(专项提交回滚/项目记录回滚/导入原子写),失败恢复链全部重写;②file:// 与部分浏览器不可用——破坏「双击 index.html 也能用」;③锁内再抛错会把「保存失败」变成「锁失败」,反馈更难解释 |
| **可合并操作记录(CRDT 日志)** | 天然收敛 | 否决:需重定义全部记录形状与备份格式,迁移成本远超双页场景收益;现有记录已按 LWW+专用决胜规则可合并 |
| **同步 saveNow + 保存前合并磁盘快照 + 纪元/终态边界**(现有模型) | 保留同步失败反馈契约;顺序读改写安全 | **采纳**。诚实边界:完全同时的多写者读改写不保证(HTML 标准本身不假定 localStorage 锁) |

## 采纳方案的依赖清单(迁移成本 = 0 的证据)

`saveNow()` 同步返回值调用点(全部保留,无需迁移):
- `views-practice.js`:笔记防抖落盘、定向会话草稿、修订确认、专项尝试提交(失败回滚 status)、saveAttempt
- `views-knowledge.js`:步骤状态、口述保存、运行记录提交(失败回滚并弹出)、口述草稿、path-drill 保存
- `store.js` 内部:clearAll/importRecords/importFull 的原子写入与回滚

## 保存前协议(saveNow 的统一行为)

1. 读磁盘;与上次写出的 raw 相同 → 直接写内存状态(无竞争);
2. 不同 → 校验磁盘数据 → `reconcileRecords(内存, 磁盘)` 按纪元/逐记录 LWW/终态守卫合并;
3. 合并结果写盘;读盘或校验失败 → 返回 false(调用方保持编辑态),不覆盖磁盘。

## 不宣称的能力(诚实边界)

- 「常规双页(含暂停恢复、顺序旧页写入)安全」有测试背书;
- 「任意多写者完全同时的读改写安全」**不宣称**——若未来需要,再评估 Web Locks + 异步迁移(成本见上表)。
